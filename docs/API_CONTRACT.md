# API contract (agreed Week 10)  - Owner: Amina A. (architecture) with Aitore + frontend
Full machine-readable version: `/api/schema/` (OpenAPI) and Swagger UI at `/api/docs/` once the backend runs.

**Errors (always):** `{ "code", "message_key", "message", "field_errors": { field: [ {message_key, message} ] } }`
Extra keys are added per error, e.g. `next_available_departure`, `locked_until`. The frontend translates `message_key`.
**401** = not logged in, **403** = wrong role. Lists are paginated: `{count, next, previous, results}`.

## Phase 2 - security and booking transaction (Week 11, Amina A.)
| Method + path | Who | Body | Success | Errors |
|---|---|---|---|---|
| POST `/api/auth/mfa/verify` | public (needs the `mfa_token` from step 1) | `mfa_token, code` (6 digits, a space in the middle is fine) | 200 `{access, refresh, user}` | 401 `invalid_mfa_code`; 401 `mfa_token_invalid` (bad or older than 5 min); **423 `account_locked`** (wrong codes count like wrong passwords) |
| POST `/api/bookings/checkout` | tourist | `departure, travelers_count, special_request?, result` (`pay`/`fail`) | 201 `{result, payment, booking}` booking is `Confirmed` | **402 `payment_failed`** = whole transaction rolled back (no booking, no payment, seats returned); 404 / 409 / 422 as for POST `/api/bookings` |

**423 Locked body:** `{code: "account_locked", message_key: "errors.account_locked", message, field_errors: {}, locked_until: <ISO time>, retry_after_seconds: <n>}` and header `Retry-After: <n>`.
Rule: 5 wrong passwords (or wrong MFA codes) -> locked 15 minutes; during the lock even the right password gets 423; an unknown email always gets 401 (never locked, never revealed).

**Role table (what each role may open):** generated by `python manage.py permission_matrix`, saved in `docs/WEEK11_AMINA_A.md`.
