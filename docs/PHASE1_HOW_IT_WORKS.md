# Phase 1 - "how it works", one block per team member (read your own part aloud once)

**Elza - Data & Database.** I designed 12 tables with integer keys. Rules live *in the database*, not only in code: CHECK (price >= 0, travelers > 0, travel_date >= booking_date, status in 5 values), UNIQUE (email, booking_ref), a partial UNIQUE index so one tourist cannot hold two active bookings of the same departure, and ON DELETE RESTRICT so nothing is orphaned. The key rule is `EXCLUDE USING gist (guide_id WITH =, tstzrange(start_at, end_at) WITH &&)`: PostgreSQL itself refuses two overlapping slots for one guide. Proof: `db/verify_constraints.sql` (22 of 22 rejected). Files: `db/*`, `backend/*/models.py`, `core/pg_constraints.py`, `seed_demo.py`.

**Aitore - Application & Development.** A tourist opens a tour (GET `/api/tours/{id}`), sees departures with the guide and seats left, enters travelers + request and POSTs `/api/bookings`. The server, not the browser, sets the price (`base_price x travelers`), the status (`Pending`) and the number (`BK-####`). Errors come back as `{code, message_key}` and Angular shows them translated; if a slot is full or already booked, the answer also contains the guide's next free departure. Files: `catalog/views.py`, `bookings/views.py`, Angular `features/*`.

**Amina S. - Systems Analysis & Requirements.** This phase turns Lab 4 into running behaviour: FR-01 (reject conflicting slot) -> exclusion constraint + `departure_full` error; FR-02 (see guide's open slots) -> departures list on the tour page; screen list so far: login, register, tour list, tour detail + booking panel, my bookings. I own the EN/RU/KZ wording in `frontend/public/i18n/*.json` (104 keys, checked by `npm run check:i18n`).

**Amina A. - Architecture & Security.** Passwords are stored only as hashes (PBKDF2). Login counts failures; the 5th wrong password locks the account for 15 minutes (HTTP 423). JWT access (30 min) + refresh (1 day); the Angular interceptor adds the token and refreshes once on a 401. Every endpoint is closed by default (`IsAuthenticated`) and opened explicitly; roles are checked on the server with `role_required(...)` (401 not logged in, 403 wrong role) - the Angular guard is only convenience. Secrets come from `.env`; the server refuses to start with a "change-me" value; the database port is not published by Docker. Booking creation is one `transaction.atomic()` with `select_for_update()` on the departure row, so two people cannot take the last seat. Files: `config/settings.py`, `core/*`, `bookings/services.py`, `docker-compose.yml`.

**Dastan - Testing, Analytics & Integration.** `/health` checks the app and the database (200 / 503). `db/verify_constraints.sql` is the first automated test. `seed_demo` loads ~50 bookings in every status so `db/analytics.sql` (active bookings per package, zero-booking packages still show 0) can be tested. Integration checklist: README "First run".
